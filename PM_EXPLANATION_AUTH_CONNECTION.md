# ?? Connection Between auth.users and public.users

## Executive Summary for PM

Yes, there are **TWO separate user systems** in Supabase that are connected via a **UUID foreign key**:

1. **`auth.users`** - Supabase's built-in authentication system (managed by Supabase)
2. **`public.users`** - Our custom application database table (managed by our app)

They are connected by the **Supabase Auth User ID (UUID)**.

## ?? The Connection Point: `userTypeId`

### Database Schema

```sql
-- public.users table
CREATE TABLE public.users (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "firstName" text NOT NULL,
  email text NULL,
  "lastName" text NULL,
  "middleName" text NULL,
  suffix text NULL,
  "contactNumber" text NULL,
  "userTypeId" text NULL UNIQUE,  -- ? THIS IS THE CONNECTION!
  "isActive" boolean NULL DEFAULT true,
  "profilePictureUrl" text NULL,
  address text NULL,
  "emergencyContact" text NULL,
  CONSTRAINT users_userTypeId_key UNIQUE ("userTypeId")
);

-- Foreign key reference (conceptual - not enforced by Supabase)
-- users.userTypeId ? auth.users.id (UUID)
```

**The `userTypeId` column stores the UUID from `auth.users.id`**

## ?? How The Connection Works in Code

### Step 1: Create User in Supabase Auth (`auth.users`)

**File:** `SupabaseAuthService.cs` ? `CreateUserAsync()` method (Line 183-234)

```csharp
public async Task<string> CreateUserAsync(string email, string password, 
    string firstName, string lastName)
{
    var gotrueClient = GetGotrueClient();
    
    // Creates entry in auth.users table
    var session = await gotrueClient.SignUp(email, password, new SignUpOptions
    {
        Data = new System.Collections.Generic.Dictionary<string, object>
  {
            { "first_name", firstName },
     { "last_name", lastName },
  { "full_name", $"{firstName} {lastName}" },
        { "needs_password_setup", true },
     { "created_at", DateTime.UtcNow.ToString("o") }
        }
    });
    
    // Returns the UUID from auth.users
    return session.User.Id;  // ? This is the UUID we use as userTypeId
}
```

**Result:** User created in `auth.users` with a UUID (e.g., `abc123-def456-...`)

### Step 3: Lookup User Using the Connection

**File:** `SupabaseAuthService.cs` ? `GetUserRoleAsync()` method (Line 622-633)

```csharp
public async Task<string> GetUserRoleAsync(string supabaseUserId)
{
    var client = await GetSupabaseClientAsync();
    
    // Query public.users using the auth.users UUID
    var userQuery = await client
        .From<SupabaseUserNew>()
        .Where(x => x.UserTypeId == supabaseUserId)  // ? Uses the UUID!
        .Get();
    
    var userRecord = userQuery?.Models?.FirstOrDefault();
    
    // Now we have the user from public.users
    // linked to their auth.users entry via userTypeId
}
```

**Result:** Can find the `public.users` record using the `auth.users` UUID

## ?? Why Two Tables?

### `auth.users` (Supabase Managed)
- **Purpose:** Authentication & Security
- **Handles:**
  - Password hashing and storage
  - Email verification
  - Password resets
  - OAuth integrations
  - Session management
  - JWT token generation
- **We DON'T control:** Schema, security rules, password encryption
- **Access:** Via Supabase Auth API (Gotrue)

### `public.users` (Our Application Database)
- **Purpose:** Application Data & Business Logic
- **Handles:**
  - User profile information
  - Contact details
  - Business logic fields (isActive, etc.)
  - Relationships to other tables
- Custom queries and reporting
- **We CONTROL:** Schema, columns, relationships, queries
- **Access:** Via Supabase Postgrest API

## ?? Key Takeaways for PM

1. **Two Systems, One Connection:**
   - `auth.users` = Authentication (login/password)
   - `public.users` = Application data (profile/business logic)
   - Connected via `userTypeId` (UUID)

2. **Security:**
   - Passwords stored securely in `auth.users` (Supabase managed)
   - Application data in `public.users` (our control)

3. **Flexibility:**
   - Can query application data without touching auth
   - Can extend `public.users` with custom fields
- Auth system handles all security concerns

4. **Standard Pattern:**
   - This is a common architecture in modern applications
   - Separates authentication concerns from application data
   - Used by: Firebase, Auth0, AWS Cognito, etc.
